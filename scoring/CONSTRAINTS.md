# Scientist Constraints

## Model

Use the provided synthetic benchmark architecture and hidden size for `synthetic_4task_merge`. All task-specific checkpoints must originate from the same pretrained backbone produced by the benchmark setup. Swapping in a larger backbone is out of scope because it improves accuracy through model scaling rather than better merging.

## Data

Use only the deterministic synthetic tasks and splits generated by `data/synthetic_tasks.py`. Do not add extra labeled data, distillation targets, auxiliary task datasets, or task-specific validation labels beyond what the reproduction explicitly provides.

## Merging Setup

The submitted system must produce one merged shared-backbone checkpoint per experiment. The benchmark has heterogeneous label spaces, so the fixed per-task output heads supplied in the artifact format are allowed and counted in the single-model parameter budget. The shared representation must not retain separate task experts, train an inference router, or require the task identity to select task-specific backbone parameter blocks at inference. Accuracy improvements must come from the merge procedure, not from ensembling or dispatching among the original fine-tuned backbones.

## Adaptation Budget

Any test-time adaptation must use only unlabeled inputs from the allowed adaptation split and must report the number of learnable adaptation parameters. Methods may change the adaptation objective or parameterization, but they must keep the reported parameter counts auditable and must not hide additional trainable state in unreported modules.

## Evaluation

Evaluate saved model artifacts on the fixed held-out task splits and report unweighted average task accuracy, balanced accuracy, worst-task accuracy, deployment parameter multiplier, and learnable adaptation parameter fraction. Labels from the evaluation split may not be used during merging or adaptation. Hardware-dependent runtime should not be used as a success criterion.

## Compliance Checklist

- [ ] Backbone architecture and hidden size match `synthetic_4task_merge` exactly.
- [ ] All fine-tuned checkpoints in an experiment share the same pretrained backbone.
- [ ] No extra labeled datasets or evaluation labels are used for merging or adaptation.
- [ ] The output is a single merged shared-backbone checkpoint, not an ensemble, router, or task-indexed backbone store.
- [ ] Learnable adaptation parameters are counted and reported.
- [ ] Evaluation uses saved model artifacts and the fixed held-out splits.
